# 08 修改与渲染节奏

什么时候读：开始渲染之前，以及用户每次提修改意见的时候。
目标是让用户尽量少等，也尽量少返工：先用最便宜的方式确认方向，确认了再花时间渲染。

## 1. 四道关，每道关都停下来等用户点头

| 关 | 产出 | 花多久 | 用户要确认什么 |
|---|---|---|---|
| ① 对标报告 | `02` 的量化报告 | 几分钟 | 拆得对不对，「参考里没有的东西」列全没有 |
| ② 静帧 | 每段 2–3 张关键帧，并排对标帧，带安全线（`--stills … --guides --sheet`） | 每张几秒 | 风格、位置、字体、颜色 |
| ③ 30 秒样片 | 最有代表性的一段（通常是开头钩子）：`--range 0 30` | 约 4 分钟 | 动起来的手感：入场、急推、时机 |
| ④ 全片 | `--out 成片.mp4` | 3–4 分钟的片约 25–30 分钟，放后台跑 | 整体节奏 |

渲染速度：贴脸字段和玻璃段大约每帧 0.27 秒，纯口播段快得多。超过 2 分钟的渲染放后台跑，不要干等。

**跳关的代价**：直接出全片，发现风格不对要整片重来。静帧能发现的问题，不要等到样片再发现。

## 2. 收修改意见的格式

让用户（或者你自己整理）按「**编号 + 时间点 + 问题 + 想要的样子**」写：

```
① 0:07.2–0:09.1  版本牌太小，看不清  → 放大到能看清 v1 v2 的字
② 0:21.3          头像压到卡片的字   → 头像挪到卡片外
③ 全片             字幕太靠下         → 抬到 y 1290
```

- 没有时间点的意见（比如「感觉不够高级」），先追问是哪几秒，或者回到 `02` 拿对标帧对照，把形容词翻译成参数。
- 一条意见对应一个参数或一段时间轴。对不上的，先问清楚再改。
- 改之前先把这张表回给用户确认：「我打算这样改：…」。

## 3. 只重渲改动的段

1. 按修改表找到受影响的 `segments`，记下它们的 `t0`–`t1`。改全局预设的意见（比如字幕位置）会影响全片，单独说明。
2. 改时间轴或那一段的 `style`。只影响一段的问题不要去改全局预设。
3. 改完先出那几处的静帧，确认后再渲染。
4. 分段渲染，再拼起来。切点必须落在段落边界上：

```
python3 scripts/compose.py timeline.json --range 0 21.3 --no-audio --out parts/01.mp4
python3 scripts/compose.py timeline.json --range 21.3 40 --no-audio --out parts/02.mp4
...
```

```
printf "file '%s'\n" "$PWD"/parts/*.mp4 > parts/list.txt      # 清单里的路径按清单所在目录解析，所以写绝对路径
ffmpeg -f concat -safe 0 -i parts/list.txt -c copy output/画面.mp4
ffmpeg -i output/画面.mp4 -i output/混音_响度统一.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 256k -shortest output/成片_v2.mp4
```

   - 第一次出全片就按段落分块渲染，以后哪段改了只重渲哪块，替换 `parts/` 里的那个文件再拼。
   - 分块都用 `--no-audio`，最后统一贴混音，避免每块的音频边界有爆音。

## 4. 版本和记录

- 每次交付带版本号：`成片_v1.mp4`、`成片_v2.mp4`。不要覆盖上一版。
- 项目里放一个 `修改记录.md`：每版改了哪几条（编号对应修改表）、重渲了哪几段。
- 用户确认过的东西写进记录里的「已定」，以后不再改，除非用户主动提。

## 5. 一轮修改的完整流程

1. 收意见，整理成修改表，回给用户确认。
2. 改时间轴或预设。
3. 出改动处的静帧（加 `--guides`），对照修改表逐条看。
4. 用户点头后，只重渲改动的分块，拼接，贴音频。
5. 更新 `修改记录.md`，交付新版本，并说明「这版改了 ①②③，没动的段落和上一版完全一样」。

## 6. 不要

- 不要为了改一处小问题整片重渲。
- 不要一轮里塞进好几处没确认过的改动，用户分不清是哪处让他满意或不满意。
- 不要把一段的问题通过改全局预设来修，会连带改坏别的段。
- 不要在用户没看过静帧的情况下直接出全片。
- 不要凭「我觉得好了」交付：每版都要过 07 的检查清单。
