# 06 配乐

什么时候读：画面和音效都定了，最后一步。分两步：先出**配乐方案**给用户选歌，用户把歌放进来以后，再**自动对点混音**。
代码在 `scripts/bgm.py`。

## 1. 选歌逻辑（参考 Johnny Harris 的《How I Use Music》）

1. **两类音乐**
   - 思考型（Thinking）：中性、有律动、偏抽象。讲信息、讲过程时用，不抢情绪。
   - 情绪型（Feeling）：打动人的那种。只给个人时刻、情绪回报和高潮用。
   - 大多数曲子介于两者之间，选曲时只问一句：它更偏哪一边？
2. **情绪要挣来**：开头不上煽情音乐。情绪曲留到观众已经投入之后，滥用会显得廉价。
3. **强度匹配**：音乐的情绪强度不能大过画面和台词本身。
4. **交替**：信息密集段之后，给一段短的感性段落让观众喘气。
5. **按形容词找歌，不按曲风找**：思考型搜 chill、curious、driving、pulse、minimal；情绪型搜 uplifting、hopeful、cinematic、peaceful。
6. **找推起点（swell）**：挑一首有明显「推起来」的曲子，把推起点对准全片最关键的那句话。

下面两条不是 Johnny 的原话，是常用的剪辑做法：

7. **换歌前留 0.3–1 秒静音**：静音能吃掉调性差异，也让下一句台词更突出。
8. **调性**：讲解段的几首歌用同调、关系调或相差纯五度；情绪段换到关系大调，小调转大调本身就是一种抬升。找不到同调的就靠第 7 条的静音过渡，不要硬变调，变调后音质会变差。

## 2. 情绪曲线（按片长比例）

一条 3–4 分钟的口播教程，默认这样排：

| 段落 | 占片长 | 类型 | 动作 |
|---|---|---|---|
| 钩子 + 框架 | 0–25% | 思考型，自信、往前推 | 第一拍就进，不淡入；讲解开始时降 2–3 dB 或抽掉鼓 |
| 主体前半 | 25–50% | 思考型，更轻、更透气 | 换章用过门，不换歌 |
| 小喘气 | 约 50% | 一个短垫音或单和弦，5–6 秒 | 前面全停，再进垫音 |
| 主体后半 | 50–83% | 思考型 | 最密的干货段，音乐保持平 |
| 结尾 | 83–100% | 情绪型（全片唯一） | 推起点对准情绪最高的那句；最后一拍干净切断 |

全片大约 80% 是思考型，情绪型只出现一次。主曲 3–4 首就够，不要每个小节都换歌。

## 3. 第一步：出配乐方案

给用户一张表，用户照着去自己有授权的曲库里找「同感觉」的歌：

```
| 段落 | 时间 | 类型 | 速度 / 调性 | 参考曲（只用来定方向） | 曲库搜索词 | 关键对点 |
```

- 参考曲只是 temp track，用来定方向。商用要用户自己去有授权的曲库找版本。
- 不替用户下载音乐。
- 每段写清楚要对齐的台词和时间，比如「推起点对准 3:10.7『打破』」。

## 4. 第二步：对点混音

1. 用户把歌放进项目的 `bgm/` 目录。
2. 找每首歌的推起点：

```
python3 scripts/bgm.py swells bgm/结尾.mp3
```

输出每个推起点的时间和抬升了多少 dB，以及最响段落的中心。抬升 2.5 dB 以上才算推起点。

3. 算 `song_start`：想让歌里 `s` 秒的推起点落在视频 `v` 秒，那一段就从歌的 `song_start = s - (v - t0)` 开始。
4. 写进时间轴：

```json
"music": {
  "pieces": [
    {"file": "bgm/开场.mp3", "song_start": 0.54, "t0": 0, "t1": 36.1, "fade_in": 0.02, "fade_out": 0.04, "gain": -3.5,
     "auto": [[15.4, 0], [15.56, -3]]},
    {"file": "bgm/讲解.mp3", "song_start": 8.0, "t0": 54.1, "t1": 105.2, "lowpass": [103.6, 105.2]},
    {"file": "bgm/结尾.mp3", "song_start": 37.1, "t0": 175.8, "t1": 211.2, "fade_out": 0.04}
  ],
  "bus_db": -14, "duck_db": -5, "lufs": -14
}
```

   - `auto`：[视频时间, dB] 的包络，用来在讲解开始时降一档。
   - `lowpass`：[开始, 结束]，在这段时间里逐渐混到 450 Hz 低通的版本，像音乐退到墙后面，用来收段落。
   - 两段之间空出 0.3–1 秒，就是换歌前的静音。

5. 混音：

```
python3 scripts/bgm.py mix timeline.json --mux output/成片.mp4
```

   - 如果已经跑过 `bgm.py sfx`，会自动和 `output/人声+音效.wav` 叠在一起。
   - 母线 EQ 是写死的：低切 70 Hz，2.8 kHz 挖 2.5 dB，给中文人声让路。
   - 有人声的地方自动再压 `duck_db`（4–6 dB），60 毫秒压下去，400 毫秒回来。
   - 最后按 `lufs` 统一响度，输出 `output/混音_响度统一.wav` 和 `_配乐版.mp4`。

## 5. 检查

| 检查 | 通过标准 |
|---|---|
| 推起点 | 对准的那句话，音乐的推起和台词前后差 ≤ 0.2 秒 |
| 电平 | 有人声时，音乐比人声低约 18–22 dB；思考段音乐单轨在 -31 到 -33 LUFS，情绪顶点在 -28 左右 |
| 换歌 | 每次换歌前都有 0.3–1 秒的静音 |
| 人声歌曲 | 口播下面没有带人声的段落，英文歌只用纯器乐段 |
| 和音效 | 音效密集的地方音乐没有 fill |
| 结尾 | 最后一拍干净切断，不是长长的淡出 |

## 6. 不要

- 不要开头就上情绪曲。
- 不要整片只用一首歌从头铺到尾，也不要每段都换歌。
- 不要让音乐盖过人声：手机外放时，字词要能听清。
- 不要为了对点硬做变速或变调。
- 不要把参考曲当成可以商用的曲子。
